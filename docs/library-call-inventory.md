# Library Call Inventory

> Companion to
> [`docs/kernel-call-inventory.md`](kernel-call-inventory.md) — same
> methodology, applied to the **library** side of the `k*` API surface that
> the kernel doc explicitly excluded. Its numbers are generated by the same
> `tools/gen-call-inventory.ps1`; never hand-edit a count, and
> `tools/verify-inventory-docs.ps1` fails on one that no longer matches the tree.

## Methodology

**Scope: library calls only, not the resident kernel.** GordonOS's 8
lazily/eagerly-loaded libraries (`src/libs/*.asm`: `time`, `filesys`, `gfx`,
`fp`, `string`, `sid`, `ipc`, `sprite`) expose their calls through the **same**
`$E000+` jump table as the resident kernel — a task can't tell from the call
site alone whether `jsr kFoo` reaches kernel-resident code or a library. The
kernel doc's methodology distinguishes them by what the jump-table slot in
`kernel.asm` initially targets:

- Resident calls `jmp` straight to a routine implemented in `src/kernel/*.inc`.
- **Library calls** `jmp libStub*` (filesys/string/time: individual cold
  stubs in `src/kernel/libstubs.inc`) or `jmp libTrap` (gfx/fp/sprite: the shared
  vector-block fail-safe in `src/kernel/lib.inc`, since these libraries are
  loaded eagerly per the caller's declared `libMask` rather than
  patched on first call) — either way, the entry only becomes the real
  routine once the library is resident, at which point `libLoad` patches the
  jump-table slot in place to `jmp <library routine>` (a 3-cycle warm
  dispatch from then on). `sprite.lib`'s four stubs sit in
  `src/kernel/sprite.inc` (`$CDDE-$DEA`) rather than `kernel.asm`, because that
  file owns the shadow block they index.
- `sid.lib` and `ipc.lib` don't get `$E000` slots at all — that table is
  full — so their four entries (`kSidPlay`/`kSidHush`/`kIpcPost`/`kIpcPick`)
  sit as 3-byte stubs in the free `$FF7E` pocket instead, following the
  identical cold-stub-then-patch pattern.

This gives **42 library call entry points** across the 9 libraries.

**Finding call sites.** Same recipe as the kernel doc: for each of the 41
names, searched `src/**/*.asm` and `src/**/*.inc` for `jsr <name>` /
`jmp <name>`, excluding full-comment lines and the `kName: jmp <target>`
definition lines themselves. A line may carry more than one call, and every one
is counted, so these are **call sites**, not lines. Library **source** files are
included as callers where relevant — e.g. `time.lib` calling `string.lib`'s
`kByteToHex` counts like any other caller.

**Excluded: the cold-stub self-completion jump.** Every lazy entry with an
individual cold stub (`libstubs.inc`'s filesys/string/time stubs, and the
sid/ipc cold stubs in `src/main.asm`) ends with a literal
`jmp kSomething` — a tail call into the entry it just patched, to complete
the very first (cold) call. That's kernel-internal plumbing, not a caller
using the API, so — mirroring the kernel doc's exclusion of internal calls
that bypass the jump table — these 23 self-referential jumps (19 in
`libstubs.inc`, 4 in `main.asm`) are excluded from the counts below. `gfx.lib`,
`fp.lib` and `sprite.lib` have no equivalent: their `libTrap` fail-safe is a
shared "you forgot to declare this library" trap, not a per-call cold-stub
trampoline, so there's nothing to exclude there.

No library-call aliases exist (checked the same `.const <name> = k[A-Z]...`
sweep as the kernel doc — the two aliases it found, `syscall` and
`csrBoth`, are both resident-kernel names, not library ones).

## Summary

- 9 lazily/eagerly-loaded libraries (`src/libs/*.asm`), 42 call entry points
  total, declared via a task's `libMask` and dispatched through the same
  `$E000+` jump table as the resident kernel calls, except the four entries
  that live in the `$FF7E` pocket
  (`kSidPlay`/`kSidHush`/`kIpcPost`/`kIpcPick`) — the `$E000` table is full.
- 38 of them have at least one call site in the current source tree; 4 have
  none.
- **208 total call sites** found across `src/`.
